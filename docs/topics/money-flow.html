Liverty Music 仕様ガイド ／ 決済・精算・返金

お金の流れ：ファンのカードから Organizer の口座まで

Liverty Music はチケット代を収納代行として受け取ります。チケットを売るのは法律上 Organizer (販売業者) で、プラットフォームはファンが払ったお金を公演後まで預かり、手数料を引いて Organizer に払います。この文書は、そのお金を「誰が・いつ・いくら・誰に」動かすかを、先着・抽選・リセールの違いとあわせて示します。

まず知っておく 3 つのこと

与信 ≠ 課金

カードは先に「押さえる」だけ。請求はチケットを渡すと決まってから

CardAuthorization (与信) は金額をカードに確保するだけです。課金 (Capture) は、先着なら注文確定のとき、抽選とリセールなら当選したときだけ行います。だからチケットを受け取らないファンには請求しません。

預かってから払う

Organizer への振込は公演開始の 7 日後

課金と同時に Settlement が Held で作られ、お金はプラットフォームに残ります。公演開始から 7 日たち、Organizer の PayoutAccount が active なら振り込みます。手数料は Organizer ごとの率 (新規は 8%) で、Settlement を作った時点で決まります。

払い戻しは 2 つだけ

返金は「中止」と「Dispute」のときだけ

自己都合の払い戻しはありません。行けなくなったファンは、席種が完売した後に公式リセールで額面のまま譲ります。出品者に戻るのは額面から 10% の手数料を引いた額です。中止の返金は admin が実行し、自動では行われません。

お金の置き場所と、動く矢印

登場するのは 3 者とカード会社だけです。支払いは Stripe を通り、ファンのお金はいったん Liverty Music の残高に入ります。Organizer の PayoutAccount は Stripe 上の受け取り用アカウントで、カード決済は受け付けません。

いつ動くか：先着・抽選・リセール

3 つの買い方は「与信をいつ置き、いつ課金するか」が違います。与信を置いてから課金するまでの間に外れたり期限が切れたりしたら、与信を解放して終わります。最後の段は 3 つに共通の、Organizer への精算です。

状態の対応：1 つの出来事で 3 つが同時に変わる

お金にかかわる記録は CardAuthorization (カードの与信)、Order (購入の記録)、Settlement (振込の記録) の 3 つです。どれも 1 つの出来事で一緒に変わり、途中だけ変わった状態は残りません。たとえば Order を Paid にするときは、券の発行と Settlement の作成も同時に行い、どれか 1 つでも失敗したら何も変えません。

Order は Pending から必ず Paid か Void のどちらかへ進みます。Void は「Paid にならなかった」、Refunded は「Paid になった後に返した」という意味で、返金できるのは Paid の Order だけです。公式リセールで請求した直後に出品が取り消されたときは、全額を返金したうえで Void になります (この請求と返金は Order に記録しません)。Event を削除できるのは、その Event の Order がすべて Void か Refunded になってからです。

手数料と Organizer の取り分

手数料は 2 種類あります。Order ごとのプラットフォーム手数料と、リセールの出品者から引くリセール手数料です。どちらも円未満は切り捨てで、端数は Organizer と出品者の得になります。

プラットフォーム手数料 (Settlement)

手数料 = floor(金額 × 率 ÷ 10000)　率は 0.01% 単位
Organizer の取り分 (split) = 金額 − 手数料

率は Organizer ごとに 0〜30% で、新しい Organizer は 8% です。admin が変えられますが、変更が効くのはそれ以降の Order だけです。Settlement を作った時点で取り分が決まるので、後から率を変えても過去の振込額は変わりません。

例：10,000 円で 8% なら手数料 800 円、取り分 9,200 円。3,333 円なら手数料 266 円、取り分 3,067 円。

リセール手数料 (ResaleListing)

リセール手数料 = floor(額面 × 10%)
出品者への返金額 = 額面 − リセール手数料

例：額面 5,000 円なら手数料 500 円、出品者への返金 4,500 円。3,333 円なら 333 円と 3,000 円。

会場費は Organizer 自身の費用で、Settlement の受取人にはなりません。決済代行 (Stripe) の手数料をどちらが負うかは、仕様には書かれていません。

リセールのお金：Organizer には 1 席につき 1 回だけ払う

リセールでは同じ席の代金を 2 人が払います。Organizer に二重に払わないよう、売れた券の分だけ元の Order の Settlement を減らし、買った人の Order には新しい Settlement を作ります。出品者への返金は振込ではなく、出品者が最初に払った決済の一部返金です。

出品者への返金は、買った人への課金から 2 分以内に行います。失敗しても 24 時間までリトライし、それでも駄目なら admin に知らせます。出品の締め切りと最後の抽選は同じ時刻で、公演当日の 12:00 (会場のタイムゾーン) と開演 3 時間前 (入場開始) の早いほうです。売れ残った券は出品者のもので、そのまま入場に使えます。

中止になったら：自動で止まるもの、admin が返すもの

member が Event を中止すると、まだ課金していない与信は自動で解放されます。課金済みの Order は自動では返金されず、admin が管理画面の Refund all で返します。中止の返金 (理由 Cancellation) は Event が CANCELLED のときしか通りません。

失敗しても二重にならない

課金・解放・返金・振込は、どれも同じ操作を何度繰り返しても 1 回分しか効きません。そのため、Stripe につながらないときは安全にリトライできます。リトライには期限があり、超えたら admin に知らせます。

起きたことどうなるか
ダブルタップ・リロード・別タブ同じ Checkout に戻り、確保・課金・発行は 1 回だけ。注文確定を 2 回押しても Issue は 1 回だけ動き、両方に同じ Order を返す。
注文確定が 30 秒で終わらない画面には Unavailable を返すが、Issue は続く。Stripe が答えれば Order は Paid になる。
課金中に Stripe につながらない課金をリトライし (先着なら確保は Committed のまま)、課金は 1 回だけ。24 時間たっても終わらなければ止めて admin に知らせる。
課金の途中で処理が止まった止まった所から再開し、もう一度は課金しない。抽選は同じ当選者のまま再開する。
与信がもう使えない (カード解約など)先着は確保を戻して Order を Void。抽選・リセールは Lost にして、当選の取り消しをメールで伝える。

取り違えやすい点

思い込みやすいこと実際の仕様取り違えると
抽選に応募した時点でお金を取る応募時は与信だけ。抽選 (Draw) 自体も課金も解放もしない。課金は当選後の OrderUseCase.Issue だけ落選者への請求や、抽選処理の中での二重課金
抽選の AuthorizeCard を呼べば応募になる応募 (Entered) になるのはカード認証の完了後に Confirm が通ったとき。ブラウザを閉じても Stripe の通知で Confirm が動く。受付終了後に作られる応募は与信を解放して作らない応募していない人を抽選に入れる、受付終了後の応募を通す
中止すれば返金も自動で走る中止で自動に止まるのは未課金の与信だけ。課金済みは admin の Refund all が必要中止したのにファンへ返金されない
振込は公演が終われば行う公演開始 + 7 日、かつ PayoutAccount が active のとき。開始時刻は毎回読み直すDispute に備える期間がなくなり、取り戻せない振込が出る
手数料率を下げれば過去分も下がる率は Settlement 作成時に固定。変更は以後の Order だけ振込額の説明が Organizer との合意とずれる
リセール出品者への返金は Organizer の取り分から出る出品者が最初に払った決済の一部返金。Organizer には元 Order の split を減らし、買った人の Order の split を足す同じ席に 2 回振り込む
リセールで売れた券も中止なら全額返す売れた券は返金しない (リセール手数料も戻らない)。返すのはまだ有効な券の額面だけ同じ席の代金を 2 人分返金する
抽選の当選者が払えなければ、次点を繰り上げる抽選は繰上げなし。その枚数は割り当てないまま。リセールは出品が次の抽選に回る販売数の超過や、抽選の公平性の崩れ
在庫の販売数にはリセールも含むTicketStock の販売数にリセールは数えない。返金済み (Refunded) の Order は数えたまま完売判定が崩れ、リセールが開かない・売り過ぎる
紹介コード (ReferralCode) で報酬を払うコードは購入を数えるためだけ。報酬もアクセス権も生まない。Order の作成時に固定払う約束のない報酬を計上する
American Express はどこでも使える先着と公式リセールは使える。抽選は使えない (カード認証の後で解放され、応募にならない)抽選で AmEx の応募を受け付けてしまう
Dispute の返金は、通常の返金と同じ返金額は 0 円です (お金はカード会社がプラットフォームから取り戻す)。公演がどの状態でも受け付け、Ticket は Voided になります。精算がまだ Held なら Reversed にして二度と払わず、Released なら払った分を Organizer から取り戻します返金額を二重に払う。あるいは、公演前の Dispute で精算が残り、Organizer に払ってしまう
決済の通知は課金の結果も受け取る決済の webhook が処理するのは、カード与信の完了と Dispute だけです。課金の完了、返金の反映、振込の取り消しなど、ほかの通知は受け取っても何もしません。署名が無効、または 300 秒より古い通知は拒否します通知を待って状態が進むと考える。実際の課金と返金は、バックエンドが自分で呼んで進める
同じ公演で席種を選び分けられる1 人のアカウントが 1 つの公演で持てる、または申し込める席種は 1 つだけです。先着・抽選・リセールのどれを通しても同じ数え方ですS 席を押さえたまま A 席も取ろうとして、弾かれる
先着は、受付期間内で残りがあれば、いつでも始められる受付が終わった抽選に、その在庫の Entered の申込みが残っている間は、先着の hold を始められません (FailedPrecondition)抽選の当選分まで先着で売ってしまう
リセールの当選者に請求できたら、必ず発券される発券の前に出品者の Order が返金 (中止か Dispute) されると、発券せず、請求した全額を当選者に返金して Order を Void にします当選者に請求だけが残る
