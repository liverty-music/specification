Liverty Music 仕様ガイド

チケットのライフサイクル

Organizer が用意した在庫 (TicketStock) から、fan の申込み、注文 (Order)、チケット (Ticket)、会場での入場、そして返金や再販による無効化までを 1 枚の地図にまとめた文書です。取得方法は先着・抽選・公式リセールの 3 つで、それぞれ申込みの形が違います。

まず知っておく 3 つのこと

  1. 申込み → Order → Ticket の 3 段で進む申込みの形は取得方法ごとに違います (Checkout / LotteryEntry / ResaleEntry)。どれも Pending の Order を 1 つだけ持ち、Order が Paid になった瞬間に Ticket が発行されます。
  2. カードは先に仮押さえ、請求は Ticket を渡す直前だけ外れた・期限が切れた・取り下げた申込みの Order は Void になり、仮押さえは請求せずに解放されます。Ticket を受け取らない fan に請求が残ることはありません (公式リセールで、請求の直後に出品が取り消されたときは全額を返金します)。
  3. Ticket の状態は Issued と Voided の 2 つだけ入場済みかどうかは状態ではなく admit time で表します。リセールは名義変更ではなく、旧 Ticket を Voided にして買った fan に新しい Ticket を発行します。

01

全体の地図

左から右へ進みます。在庫から 3 種類の申込みが生まれ、どれも 1 つの Order に行き着きます。Ticket は出品されると再びリセールの供給に戻ります。

02

在庫の数え方

TicketStock は 1 公演 (Event) の 1 SeatType ぶんのチケットです。公演と SeatType の組に 1 つだけで、同じ公演のすべての TicketSale (先行・一般など) が同じ在庫から売ります。だから先行抽選で当選した枚数は、一般販売の残りから自動的に引かれます。状態は属性として持たず、その時点の Order から数えます。

sold 100
remaining 44
sold 100Paid・Refunded の Order と、Committed の Checkout・Won の LotteryEntry を持つ Pending の Order の枚数。リセールで買われた枚数は数えない。
held 6hold 中 (Held かつ 15 分以内) の Checkout の枚数。
remaining 44quantity − sold − held。0 未満にはならない。
在庫の状態条件意味すること
SoldOutsold = quantityこの SeatType の公式リセールが開く (締切まで)
AllHeldremaining = 0 かつ sold < quantity他の fan の hold が切れれば買える。リセールは開かない
Availableそれ以外remaining が quantity の 1/10 (切り上げ) 以下なら LowStock

SoldOut の後でも、請求できずに確定を取り消された分が戻ると Available に戻り、リセールは閉じます。閉じるのは新しい出品と申込みだけで、すでにある出品と申込みは次の抽選でそのまま割り当てます。

ルール理由・破ると何が起きるか
1 アカウントが 1 公演で持てる枚数は per-account limit まで (1〜10、指定がなければ 4)。すべての TicketSale・SeatType・公式リセールの合計で数える同行者は 1 つの入場 QR コードでまとめて入場し、1 つのコードで提示できるのは 10 枚まで
1 公演で持つ・申し込む SeatType は 1 種類だけ先行で S席に当選した fan は、一般で A席を申し込めない
1 つの抽選 TicketSale に、1 公演につき 1 回だけ申し込める2 回目の申込みは拒否され、仮押さえは解放される
二重タップ・リトライ・再読み込み・別タブでも、hold・請求・発行は 1 回fan が二重に請求されない
本人確認が必要な TicketSale では、Active な IdentityVerification が無いと hold も申込みもできない。公式リセールは、その公演のどれか 1 つの TicketSale が本人確認を必須にしていれば必要拒否され、何も押さえない。発券する Ticket はその IdentityVerification に紐付く
受付が終わった抽選に、その在庫の Entered の申込みが残っている間は、先着の hold を始められない抽選がまだ当選分を在庫から引いていないので、先着で売ると当選者の分まで売ってしまう

先着: Checkout の状態

抽選: LotteryEntry の状態

公式リセール: 出品 (ResaleListing) と申込み (ResaleEntry)

在庫が SoldOut になると、その SeatType の Ticket を持つ fan は 1 枚ずつ券面価格で出品でき、別の fan は枚数を指定して申し込めます。毎日 12:00 の抽選が、出品をランダム順の申込みに「全員分か 0 枚か」で割り当てます。出品者には券面価格から手数料 10% (円未満切り捨て) を引いた額が返金されます (5000 円なら 4500 円)。

リセールで買われた枚数は在庫の sold に数えません。売れた後も在庫は SoldOut のままです。Organizer への支払いは 1 席につき 1 回分で、リセールの前後で変わりません (端数は 1 枚あたり 1 円以内)。

04

Order とカード

Order は、1 アカウントが 1 つの TicketStock に出した申込みで、支払い後はそのまま購入記録になります。Order は必ずちょうど 1 つの申込み (Checkout・LotteryEntry・ResaleEntry のどれか) から作られ、金額は作成時に「SeatType の価格 × 枚数」で固定されます。カード番号・有効期限・セキュリティコードは保存せず、表示用にブランドと下 4 桁だけを持ちます。

ルール理由・破ると何が起きるか
Void になれるのは Pending からだけ一度 Paid になった Order を「払われなかった」扱いにしない
返金できるのは Paid の Order だけ。理由は中止 (Cancellation) か Dispute (カード会社による払い戻し)中止の返金は、公演が CANCELLED のときしか通らない
中止の返金額は「まだ Issued の Ticket の分」リセールで売れた Ticket は手数料を引いて返金済みなので、二重に返さない
請求の処理は止まっても途中から再開し、カードを二度請求しない。24 時間たっても終わらなければ admin に知らせる決済代行が落ちていても、復旧後に 1 回だけ請求される
仮押さえの解放は、決済代行に届くまで 24 時間リトライし、失敗したら admin に知らせるVoid の Order の仮押さえが黙って残り続けない
抽選では American Express のカードを受け付けない (先着と公式リセールは受け付ける)抽選の申込みは成立せず、仮押さえは解放される

公式リセール: 請求の直後に出品が取り消されたとき

当選者に請求したあと、発券する前に、出品した fan の Order が返金される (中止か Dispute) ことがあります。このときは何も発券せず、請求した全額を当選者に返金してから、ResaleEntry を Lost (listing cancelled)、Order を Void にして、当選者に知らせます。返金が終わるまで Lost にしないので、チケットが無いまま請求だけが残ることはありません。

発券のあと: 精算と Dispute

課金と同時に、Organizer への支払い予定 Settlement が Held で作られます。支払われるのは、公演の開始時刻から 7 日を過ぎ、Organizer の PayoutAccount が Active のときです。開始時刻が未定の公演や、口座の準備が終わっていない間は Held のままです。

カード会社が Dispute を開くと、公演がどの状態でも Order は Refunded になり、Ticket はすべて Voided になります。お金はカード会社が引き戻すので、返金額は 0 円で、fan への返金の連絡はしません。Settlement は Reversed になり、支払い済みなら Organizer から取り戻します。

05

Ticket と入場

Ticket は 1 公演への入場の権利 1 枚で、fan のアカウントに紐付く特定興行入場券です。券面には公演・利用者・「主催者の同意のない転売は禁止」を載せ、座席は指定しません。氏名と電話番号は Ticket にコピーせず、User の今の値を表示します。Ticket の user は後から変わりません。

入場できるのは 4 通りのうち 1 つだけ

admit time なし
admit time あり
Issued
入場できるここで初めて Admission を記録する
入場済み再スキャンは AlreadyAdmitted。前回の時刻と受付番号を表示
Voided
無効返金かリセールで無効化された
入場後に無効admit time と Admission は消えない

入場の記録 (Admission) は書き換えも削除もしません。入場後に Dispute で返金されても、来場した証拠として残します。

会場での判定

fan のスマホは、登録した鍵で署名した入場用 QR コード (AdmissionCode) を通信なしで作り、15 秒ごとに作り直します。1 つのコードで同行者分を含む 1〜10 枚を提示できます。スタッフはアカウントを持たず、Organizer が発行した Scanner のリンクを最初に開いた端末だけが読み取りに使えます。

06

1 公演の時間軸

例: 19:00 開演の公演。先行抽選の後に一般の先着販売があり、売り切れてからリセールが開く場合です。左側は数週間を縮め、当日だけを拡大しています。

一般の先着販売は、先行抽選の締切と同時に始まっても、その抽選の申込みが Entered で残っている間は開始できません。当選分を在庫から引く前に売ってしまわないためです。

07

公演が中止になったら

member が Event を中止にすると、Event は PUBLISHED から CANCELLED になり、元に戻せません。新しい hold・申込み・出品はすべて拒否されます。すでにある申込みと Order は、下の表のとおりに終わります。

対象どうなるかいつ
Checkout (hold 中)注文確定が失敗し、請求されない。hold は期限で Expired になり、仮押さえは解放注文確定のとき
LotteryEntry EnteredLost (公演中止)、仮押さえ解放、メールと push。同じ sale の他の公演の申込みはそのまま抽選へ中止の直後。抽選の窓の終了を待たない
LotteryEntry Wonまだ請求していなければ Lost にして請求しない。請求済みなら Order は Paid になり、他の Paid の Order と一緒に返金請求を試みるとき
ResaleEntry EnteredLost (公演中止)、仮押さえ解放、通知次の抽選時刻
Paid の Order自動では返金しない。 admin が Artist concerts 画面の Refund all で返金すると Refunded になり、Ticket はすべて Voided、出品中の ResaleListing は Cancelledadmin の操作
fan への通知Issued の Ticket を持つ Paid の Order の fan に、中止の連絡 (メールと push)。返金したときに金額とカードを載せた返金の連絡。全 Ticket をリセールで売った fan には送らない中止時と返金時に各 1 回
Event の削除Paid か Pending の Order が残る間は失敗する。Void と Refunded だけになれば、Event と一緒に消える (最後の Event なら Series も)返金の後
08

TicketJourney は別物

TicketJourney は、fan が「この公演のチケットについて自分は今どこにいるか」を記録するメモで、Timetable や公演シートに表示されます。fan が手で設定でき、実際の Order や Ticket とは照合しません。状態は 5 つで、どの状態からどの状態へも変えられます。

Tracking 販売情報を待つ Applied 抽選に申込み済み Lost 落選・入金期限切れ Unpaid 入金待ち Paid チケット確保
誰が記録するかいつ既存の記録を上書きするか
fanいつでも、どの状態でも上書きする
platformLotteryEntry ができたとき → AppliedUnpaid・Paid は上書きしない。記録の失敗で申込みは失敗しない
platformOrder が Paid になったとき → Paid何でも上書きする
アプリの推定公演をカレンダーに追加したとき → Tracking記録がないときだけ
09

取り違えやすい点

取り違え正しくは取り違えると
Order の Void と Ticket の Voided は同じVoid は「一度も Paid にならずに終わった Order」。Voided は「無効になった Ticket」で、その Order は Paid か Refunded のままリセールで売れた Ticket の Order を未払い扱いにし、返金額や支払いを誤る
入場済みは Ticket の状態の 1 つ状態は Issued と Voided だけ。入場は admit time と Admission で表し、Voided にしても消えない返金で来場の証拠を消し、chargeback に反論できなくなる
リセールは Ticket の名義変更旧 Ticket を Voided にし、買った fan に新しい Ticket を発行する。Ticket の user は変わらない出品者のコードで入場できてしまう、または買った fan が入場できない
公演を中止すれば返金されるPaid の Order は admin が Refund all するまで Paid のままfan に返金されないまま Event を削除しようとして失敗する
申込みの時点で請求される申込みでは仮押さえだけ。請求は先着の注文確定と、抽選・リセールの当選の後だけ落選者への請求、または仮押さえの解放漏れ
抽選で当選が取り消されたら次点に回るLotteryEntry に繰上げ当選はなく、その枚数は割り当てられずに在庫へ戻る。リセールでは、その出品が次の抽選で再び割り当て可能になる抽選結果の説明や在庫の数を誤る
ResaleEntry の Lapsed は落選Lapsed は仮押さえの期限が近くて抽選に参加できなかった状態。再申込みを案内する再申込みできる fan に「落選」と伝えてしまう
リセールで売れた枚数も在庫の sold に入る入らない。売れた後も在庫は SoldOut のまま同じ席を 2 回数え、在庫と Organizer の支払いを誤る
TicketJourney の Paid はチケットを持っている証拠fan が手で設定でき、実際の Ticket とは照合しないJourney を見て入場可否や返金を判断してしまう
1 つの公演で、席種を変えて申し込める1 人のアカウントが 1 つの公演で持てる、または申し込める席種は 1 つだけです。販売 (先行・一般) をまたいでも同じで、抽選は 1 公演につき 1 回しか応募できません先行で S 席を押さえたまま、一般販売で別の席種も買えると思い込む
